## The problem

An existing integration sent sales from the point of sale system Cashr, through Reeleezee, to the accounting in Exact Online. An outside party had built it. There was no documentation and no source code.

It had three problems:

- Card payments arrived as one group total instead of per item.
- Receipts paid "on account" were never marked as processed, so the open balance kept growing.
- A revenue report per product was missing items.

## The approach

Without source code, the only way in was from the outside: looking at what the integration is allowed to do, and at what it leaves behind in each system.

### Reading the data flow

The app permissions showed which data the integration can reach. The Reeleezee REST API, with roughly 2,100 endpoints, showed what actually arrives there. Python scripts read the data on both sides, so the two could be laid side by side.

### The mapping rule

That comparison revealed the rule that maps an item code in the point of sale system to an item code in the accounting. It also revealed the API actions that mark a receipt as processed, which is the step the "on account" receipts never reached.

### A diff script for the catalogue

A diff script compares the product catalogue of both systems line by line and reports every product that points to a different item on the other side.

## The result

The full data flow is now mapped, from the till to the books.

The diff script found wrong item mappings with wrong VAT rates. These were products that ended up on the wrong item, and so at the wrong rate.

The next step is planned as a golden master test: running the integration against real invoices and comparing the output with a result that is known to be correct.
