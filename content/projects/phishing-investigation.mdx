## The problem

Customer data from a website was ending up outside the systems it belonged in. That data passes through several systems, and it was unclear which of them was leaking.

## The approach

### Reading the logs

The firewall and application logs were the starting point. They showed that a vulnerable WordPress plugin was actively being probed on several sites. They also showed attempts to reach a suspicious PHP file in the uploads folder, which is a common place for a backdoor.

### Isolating the leak with canary records

Each system the data passes through could be the leak. The test plan uses canary records: test entries with contact details that are unique per system. If one of those details is misused, it shows which system the data came from.

## The measures

- Update the vulnerable plugin on every site.
- Replace the API keys, so keys that may have leaked stop working.
- Check the sites for backdoors.

The canary records also serve as the check afterwards: as long as none of them is misused, the leak is closed.
